## 🎯 プロジェクト概要

### 目的
鍼灸院オーナー（メルマガ会員 約8,500院）への業界実態調査。「当社ツール（しんきゅう予約）を予約台帳として使ってもらえない理由」の解明が戦略的目的。

### 主要スペック
- **回答時間**: 4.5〜6.5分
- **設問数**: 14設問（うち分岐2か所、実質8〜11問）
- **想定回収数**: 425〜850件（5〜10%）

### 技術スタック
- **フロントエンド**: HTML + CSS + JavaScript（フレームワーク不要）
- **ホスティング**: GitHub Pages
- **データ保存**: Google Sheets API
- **対応デバイス**: モバイルファースト（スマホ・タブレット・PC）

## ⚠️ 実装時の重要な注意点

### 1. 分岐ロジック（特に重要）

**Q3 → Q4 の分岐**：
- Q3=「予約管理ツール」を選択した場合のみ Q4 を表示
- それ以外は Q4 をスキップして Q4-2 へ

**Q9 → Q10 の分岐**：
- Q9=「とても興味あり」または「条件次第で興味あり」を選択した場合のみ Q10 を表示
- それ以外は Q10 をスキップして Q11 へ

### 2. 動的フィルタリング（Q4-2）

Q4で予約管理ツールを選んだ場合、対応するサービスをQ4-2の選択肢から自動除外する：

| Q4の選択 | Q4-2から除外する選択肢 |
|---|---|
| ホットペッパービューティー(サロンボード) | ホットペッパービューティー(サロンボード) |
| EPARK | EPARK |
| エキテン | エキテン |
| 健康にはり | 健康にはり |
| しんきゅう予約 | しんきゅう予約・しんきゅうコンパス |
| LINE連携ツール | LINE公式アカウント |
| ホームページの予約フォーム | 自院のホームページ |

**例外**: Q4=「その他」を選んだ場合は除外処理を行わず、Q4-2に全選択肢を表示。

### 3. 動的文言切り替え（Q4-2の最終選択肢）

Q3の回答により、Q4-2の最後の選択肢の文言を切り替え：

| Q3の選択 | Q4-2の文言 |
|---|---|
| 紙、Excel、Googleカレンダー、その他 | 「ネット集客は活用していない」 |
| 予約管理ツール | 「Q4で選んだサービス以外には活用していない」 |

### 4. 動的選択肢出し分け（Q5・Q6）

Q5（困りごと）とQ6（気に入っている点）は、Q3の回答により表示選択肢を変更：

- 詳細マトリクスは `survey_spec.md` の「3.3 Section C」を参照
- YAMLでは各選択肢に `visible_when` で表示条件を定義済み

### 5. 排他選択

以下の選択肢は、選択時に同じ設問内の他の選択肢を自動的にチェック解除：

- **Q4-2**: 「ネット集客は活用していない」/「Q4で選んだサービス以外には活用していない」
- **Q5**: 「特に困っていない」
- **Q6**: 「特になし」
- **Q7**: 「特に不安はない」

YAMLでは `exclusive: true` で指定済み。

### 6. データ保存形式

**複数選択の保存**: カンマ区切り文字列
- 例: `double_booking,input_mistakes,hard_to_read`

**重複回答の処理**: 同一メールアドレス（Q2）の場合は既存レコードを上書き

**列構成**: `survey_spec.md` の「5. データ保存仕様」を参照

## 🔑 重要な戦略コンテキスト（実装に影響しないが、判断時の参考）

### 本アンケートの戦略的位置づけ

1. **核心の問い**: 当社ツール（しんきゅう予約）を予約台帳として使ってもらえないのはなぜか？
2. **業界実態の前提**: ネット予約の必要性は既に約90%が同意済み。本アンケートは「乗り換え意向と障壁の確認」が目的。
3. **検証する戦略仮説**: A〜K の11個（詳細は `survey_spec.md` の「9. 戦略仮説と分析設計」参照）

### マトリクス分析の構造

- **行**: Q3（予約台帳の種類）× Q4（予約管理ツール名）
- **列**: Q9（改善への興味）
- **補助軸**: Q4-2（集客チャネル）

### 最優先セグメント

| Q3 | Q4-2 | Q9 | 戦略的意味 |
|---|---|---|---|
| 紙 | しんきゅうコンパス含む | あり | **★既存ユーザー×予約台帳化候補** |
| 紙 | しんきゅう＋他社併用 | あり | **★複数併用×一体化訴求** |

## 🤝 不明点・確認事項があった場合

実装中に以下の点で判断が必要になった場合は、実装を進める前に CS マネージャー（北原）に確認してください：

### 確認すべき事項

| 項目 | 確認内容 |
|---|---|
| ブランドカラー | しんきゅうコンパスの正式なブランドカラー（CSSで使用） |
| プライバシーポリシー | アンケート冒頭に表示する文言・リンク先 |
| Google Sheets API認証方法 | APIキー方式 or Apps Script Webアプリ方式 |
| Q4のサービス選択肢 | 業界実態に照らして追加・削除すべきものがないか |
| Q4-2の選択肢順序 | 患者利用数の多い順となっているか、社内データとの照合 |
| メルマガ配信時の文面 | アンケートへの誘導文の作成有無 |

### 実装中の判断原則

1. **仕様書とYAMLが正** ：両者に齟齬がある場合は仕様書を優先
2. **シンプル優先** ：機能を盛り込みすぎず、本来の目的（戦略仮説検証）を最優先
3. **モバイル優先** ：すべてのUIはまずスマホで動作確認
