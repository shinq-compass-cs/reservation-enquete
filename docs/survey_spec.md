## 1. プロジェクト概要

### 1.1 目的

しんきゅうコンパス（鍼灸院口コミ・予約ポータル）のメルマガ会員約8,500院に対して、予約管理の実態と乗り換え意向・障壁を把握するためのオンラインアンケート。

**戦略的目的**：「当社ツール（しんきゅう予約）を予約台帳として使ってもらえない理由」を明らかにすること。

### 1.2 配信概要

| 項目 | 内容 |
|---|---|
| 送付対象 | メルマガ会員 約8,500院 |
| 配信チャネル | メールマガジン |
| 想定回収数 | 425〜850件（5〜10%） |
| 回答時間目安 | 4.5〜6.5分 |
| 回答インセンティブ | 集計結果レポートの還元 |

### 1.3 アンケート構造

| Section | 内容 | 設問数 |
|---|---|---|
| A | 基本情報 | Q1〜Q2 |
| B | 現在の予約台帳と集客 | Q3〜Q4-2 |
| C | 課題・ニーズ把握 | Q5〜Q7 |
| D | 利用シーン把握 | Q8 |
| E | 今後への関心 | Q9〜Q10 |
| F | 自由記述 | Q11 |

**総設問数**: 14設問（うち分岐2か所、実質8〜11問）

#### Q4-2. 集客やネット予約受付のために使っているサービスはありますか？
- **形式**: 複数選択（チェックボックス）
- **必須**: はい
- **表示条件**: 全員に表示

**選択肢（全パターン）**:
1. ホットペッパービューティー（サロンボード）
2. EPARK
3. エキテン
4. 健康にはり
5. しんきゅう予約・しんきゅうコンパス
6. LINE公式アカウント
7. 自院のホームページ
8. Instagram・SNS
9. その他（自由記述）
10. **動的文言**:
   - Q3=紙・Excel・Googleカレンダー・その他 → 「ネット集客は活用していない」
   - Q3=予約管理ツール → 「Q4で選んだサービス以外には活用していない」

**動的フィルタリングロジック**:
- Q3=「予約管理ツール」かつQ4で選択したサービスがQ4-2の選択肢にある場合 → そのサービスをQ4-2から自動除外
- Q4=「その他（自由記述）」を選んだ場合 → 除外処理を行わず、全選択肢を表示

**排他選択ロジック**:
- 「ネット集客は活用していない」または「Q4で選んだサービス以外には活用していない」を選択 → 他の選択肢を自動的にチェック解除

## 5. データ保存仕様

### 5.1 Google Sheets 構成

**シート名**: `survey_responses`

**列構成**:

| 列 | 内容 |
|---|---|
| timestamp | 送信日時（ISO 8601形式） |
| q1_clinic_name | 院名 |
| q2_email | メールアドレス |
| q3_management_type | Q3の回答（選択肢の値） |
| q3_other_text | Q3で「その他」を選んだ場合の自由記述 |
| q4_reservation_tool | Q4の回答（該当者のみ） |
| q4_other_text | Q4で「その他」を選んだ場合の自由記述 |
| q4_2_marketing_channels | Q4-2の回答（カンマ区切りで複数値を保存） |
| q4_2_other_text | Q4-2で「その他」を選んだ場合の自由記述 |
| q5_difficulties | Q5の回答（カンマ区切り） |
| q6_likes | Q6の回答（カンマ区切り） |
| q7_concerns | Q7の回答（カンマ区切り） |
| q7_other_text | Q7で「その他」を選んだ場合の自由記述 |
| q8_recording_timing | Q8の回答（カンマ区切り） |
| q9_interest_level | Q9の回答 |
| q10_required_conditions | Q10の自由記述（該当者のみ） |
| q11_free_comment | Q11の自由記述 |
| user_agent | ブラウザ情報（デバッグ用） |
| completion_time_seconds | 回答所要時間（秒） |

### 5.2 データ型と形式

- **複数選択の保存**: カンマ区切りの文字列で保存（例：`option_1,option_2,option_5`）
- **値の表現**: 各選択肢には一意の ID（英数字）を持たせる（YAML定義参照）
- **タイムスタンプ**: ISO 8601 形式（例：`2026-05-27T14:30:00+09:00`）

### 5.3 重複回答の処理

**方針**: 同一メールアドレスからの再回答は **上書き** とする。

**実装**:
1. 送信時、`q2_email` で既存レコードを検索
2. 存在する場合：既存レコードを更新（最終回答が有効）
3. 存在しない場合：新規レコードを追加
